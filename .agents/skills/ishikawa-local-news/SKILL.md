# 石川ローカルニュース

うるま市石川地区で暮らす人に関係する情報を、見落としを減らしながら安全に収集・選別する。
「広く集める段階」と「公開する段階」を分け、候補になっただけの情報を自動的に事実として公開しない。

複数地域へ展開する共通設計、新地域の初回棚卸し、地域設定の追加は`$regional-local-news`を使用する。このSkillは石川固有の運用、情報源、判定例を扱う。

## 対象

- 地域ニュース、行政・公共施設のお知らせ
- 催し、祭り、闘牛、エイサー、講座、募集（石川多目的ドームの大会日程を含む）
- 防災、交通規制、工事、休館などの生活情報
- 石川地区の学校、自治会、地域団体の活動
- 店舗・施設の開店、閉店、移転、臨時営業などの時事情報
- 管理人投稿、承認済み読者投稿

店舗の住所・営業時間などを`restaurants-data.js`へ恒久登録する調査は`$poi-survey`を使用する。歴史・地理・人口などの地区紹介は`$area-profile`を使用する。

## 作業モード

依頼に合うモードだけを行う。

1. **情報源整備**：取得先の追加・停止・優先度変更。先に[情報源方針](references/source-policy.md)を読む。
2. **候補収集**：広く取得し、石川関連度を判定して候補一覧を作る。[関連度判定](references/relevance-rules.md)を読む。
3. **候補確認**：判断保留や監査記録について、依頼された場合だけ重複、原典、日時、場所、期限、反証を確認する。
4. **データ反映**：候補JSONや生成処理へ反映する。[候補データ形式](references/article-schema.md)を読む。
5. **自動更新改修**：`scripts/fetch_news.py`と`.github/workflows/fetch_news.yml`を変更し、生成結果まで検証する。

調査だけの依頼では、生成ファイル、公開データ、GitHub Actionsを変更しない。

うるま市公式サイトの常設ページから開催情報を収集するときは、[情報源方針の「公式ページ内の時事情報」](references/source-policy.md#公式ページ内の時事情報)を読む。

## 基本原則

1. **収集と公開を分ける。** 取得した情報はまず候補とし、関連度と信頼度を判定する。
2. **原典へ到達する。** 検索結果の見出しや転載だけで判断せず、可能な限り発信元を開く。
3. **場所の根拠を残す。** 「石川」という語だけで採用せず、うるま市石川との関係を示す語句・施設・住所を記録する。
4. **出典と時刻を残す。** 原典URL、発信元、公開日時、発見日時、確認日時を保持する。
5. **要約を創作しない。** 原典にある事実だけを短く言い換え、推測や評価を足さない。
6. **本文を転載しない。** タイトル、短い事実要約、出典リンクを基本にする。
7. **不明を保留できる設計にする。** 判断材料が足りない候補は`review`とし、自動掲載しない。
8. **重要情報は慎重に扱う。** 事故、災害、犯罪、閉店、人物に不利益を与え得る情報は、公式発表または信頼できる複数ソースを確認する。

## 通常の自動運用

毎日の収集では、管理人の確認を前提にせず、候補を次の3経路へ自動分類する。

1. **自動掲載**：石川地区との関係、配信元へのリンク、公開日時、重複なしを確認でき、慎重な確認を要する内容でない。
2. **自動除外**：石川県・人名などの誤一致、地域根拠不足、または掲載対象外と明確に判定できる。
3. **判断保留**：地域との関係や日時、情報源を確定できない、または事故・犯罪・訃報・閉店など慎重な確認が必要。公開せず監査記録へ残す。

判断保留は日常的な管理人作業を要求しない。次回収集で新しい根拠が得られれば再判定し、掲載期間を過ぎたら期限切れ記録へ移す。管理者ページは選択画面ではなく、自動処理を必要なときだけ確認する監査画面として扱う。

写真ギャラリー、転載、媒体違いの同一内容は、[関連度判定の重複規則](references/relevance-rules.md)に従って代表1件だけを公開する。除いたURLは代表候補の`relatedUrls`へ残し、情報源を失わない。

## 標準ワークフロー

### 1. 現在の状態を確認する

- `AGENTS.md`とGit状態を確認し、既存の未コミット変更を保護する。
- `scripts/fetch_news.py`、`.github/workflows/fetch_news.yml`、`news/today.json`、`news/no_news_dates.json`を確認する。
- 公開状態を調べる場合は、ローカルの古い生成物だけで判断せず、`origin/main`または公開ページの更新日時も確認する。

### 2. 候補を収集する

- 情報源ごとに取得成否を記録し、取得失敗を「ニュースなし」と混同しない。
- 同じ出来事が複数サイトにある場合も、候補段階では原典ごとに保持してよい。
- SNSや投稿情報は、取得・再利用条件と公開範囲を確認し、本文や画像を無断転載しない。

### 3. 判定する

- [関連度判定](references/relevance-rules.md)に従い、`localScore`と根拠を付ける。
- 情報源の種類、原典到達可否、日時の明確さから`confidence`を付ける。
- 高得点でも、重要情報や曖昧な投稿は`review`にする。
- タイトル表記、正規化URL、出来事、日時・場所を使って重複をまとめる。

### 4. 掲載期間を決める

- 通常ニュースは公開後7日を基本とする。
- 未来のイベントは終了日まで掲載できる。終了日時が分かる場合は終了後に外す。
- 募集、通行止め、休館などは期限を優先し、単純な7日制限だけで消さない。
- 終了日不明の情報は推測せず、短い期限または`review`を選ぶ。

### 5. 反映・生成する

ユーザーが実装を依頼した場合だけ行う。

- 恒久的なレイアウト・文言・収集条件は`scripts/fetch_news.py`へ反映する。
- `news/index.html`は自動生成物なので、単独で恒久修正しない。
- 即時確認のため生成物も更新する場合は、生成スクリプトと結果を同じ内容にそろえる。
- 収集結果と表示件数、リンク、日付順、重複、空の日表示を確認する。
- GitHub Actionsの変更は手動実行と毎朝6時の定期実行の両方を壊していないか確認する。
- コミット、プッシュ、公開はユーザーが明示的に許可した場合だけ行う。

## 自動掲載の境界

次をすべて満たす候補だけを自動掲載候補にできる。

- うるま市石川との関係が明確
- 原典URLへ到達できる
- タイトルと公開日時を確認できる
- 誤認しやすい「石川県」「石川姓」などを除外できる
- 重複判定を通過している
- 事故・犯罪・閉店など、管理人確認を必須とする種類ではない

それ以外は`review`へ送る。自動掲載基準の緩和は、実際の候補と誤判定例をユーザーへ提示してから行う。

## 完了条件

- 候補ごとに原典、日時、地域根拠、関連度、信頼度、状態がある。
- 取得失敗、対象なし、期限切れを区別している。
- 石川県・人名などの誤一致と重複を確認した。
- 高影響情報を未確認のまま公開していない。
- 生成処理を変更した場合、`fetch_news.py`と生成物の整合を確認した。
- 対象外ファイルや既存のユーザー変更を混ぜていない。
