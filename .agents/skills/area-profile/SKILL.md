# 地区プロファイル調査

地図サイトで扱う地区の紹介文を、公共機関の一次情報を優先し、複数ソースで照合して作成・更新する。
石川地区で確立した手順を、具志川・勝連・与那城や他地域にも適用できる形で運用する。

## 基本原則

1. **モデルの記憶だけで書かない。** 実在するページや公文書を開いて確認する。
2. **公共機関を最優先する。** 市町村公式 > 都道府県公式・公文書館 > 観光協会・公民館 > その他の順に扱う。
3. **丸写ししない。** 事実を抽出し、著作権に配慮して自分の言葉で再構成する。
4. **出典と調査日を表示する。** 読者が一次情報を確認できる状態にする。
5. **数値と文章を分ける。** 人口などの数値は定期更新し、歴史・文化の文章は根拠や意味が変わる場合だけ人の確認を経て変更する。

## 禁止事項

- モデルの知識だけで歴史や地名の由来を書かない。
- 公式サイトの文章をそのままコピーしない。
- 出典のない数値や概数を書かない。
- 推測を断定で書かない。公共機関1件だけに基づく場合は出典を明示するか、断定を弱める。
- GoogleマップやNTTタウンページを自動収集しない。
- 検索結果の要約だけを根拠にしない。必ずリンク先の本文を開く。
- ユーザーの明示的な許可なしに、コミット、プッシュ、公開、本番データの変更を行わない。

## 作業手順

### 1. 準備する

- 対象地区と所管自治体を確定する（例：石川地区 → 沖縄県うるま市／旧石川市）。
- `AGENTS.md`と現在のGit状態を確認し、既存の未コミット変更を保護する。
- 最新状態との同期が必要な場合は、作業ツリーが安全であり、ユーザーの意図に沿うことを確認してから行う。
- 下の「地区別の情報源」に対象地区があれば再利用し、なければ新しく情報源リストを作る。

### 2. 情報源リストを作る

次の順で探し、採用候補のURLとページ更新日を記録する。

| 優先 | 種別 | 検索例 |
|---|---|---|
| 1 | **教育委員会・文化財課のリーフレット／文化財シリーズ（PDF）** | `(市町村名) 文化財シリーズ (地区名)` `(市町村名) 教育委員会 (地区名) パンフレット filetype:pdf` |
| 2 | **郷土資料館・歴史民俗資料館の公式ページ** | `(市町村名)立 (地区名) 歴史民俗資料館` |
| 3 | 市町村公式の地区紹介ページ | `(市町村名) (地区名) 紹介` `site:city.xxx.lg.jp` |
| 4 | 市町村公式の統計ページ | `(市町村名) 大字別人口 統計` |
| 5 | 市町村公式の「市の紹介」「あゆみ」「歴史」 | `(市町村名) 市の紹介 合併 由来` |
| 6 | 都道府県公文書館・県公式 | `(都道府県) 公文書館 (地区名)` |
| 7 | 観光協会・物産協会など公的性格の強い団体 | `(市町村名) 観光協会 (地区名)` |
| 8 | 公民館・図書館・市史 | `(地区名) 公民館` `(市町村名) 市史` |

教育委員会の文化財資料と資料館の公式情報を最優先する。一般向け紹介ページよりも、年月日、人数、固有名詞、地域で重視される出来事が詳しい場合が多い。

- 利用可能なWeb閲覧手段で検索し、候補ページを実際に開いて本文を確認する。
- 個人ブログ・まとめサイトは発見の手がかりに限り、事実の根拠にはしない。
- Wikipediaは調査項目の発見に限って使い、採用する事実は公共機関の資料で確認する。
- 特定ページやPDFを扱うときは、検索結果ではなく、そのページまたは文書を直接確認する。

### 3. 本文から事実を収集する

各URLを開き、次の観点で事実を漏れなく抽出する。

```text
このページに書かれている対象地区の事実を漏れなく列挙する。
地理・地形、歴史（年号と出来事）、文化・伝統、産業、観光・施設、
面積・人口などの数値を、記載どおりに抽出する。
ページにない内容は推測せず「記載なし」とする。
```

抽出した事実には、URL、資料名、ページ更新日または発行日、確認日を対応付ける。長い資料を要約する前に事実リストを作り、本文完成後に1件ずつ照合できる状態にする。

### 4. 人口・世帯数を取得する

市町村公式の統計ページから「大字別人口及び世帯数」などの最新資料を探す。

1. 統計ページを開き、PDFや表の直リンク、対象年月、ファイル名規則を確認する。
2. 最新資料をWebまたはPDFを扱える手段で直接読む。テキスト抽出に失敗した場合は、ローカルPDFの抽出、ページ画像の確認、表の目視確認など、利用可能なPDF読取手段へ切り替える。
3. 対象地区に属する大字を全件拾い、各行の人口・世帯数と対象範囲を記録する。
4. 合計は暗算せず、ターミナルでPythonなどを実行して再現可能な形で計算する。

```python
pop = {'石川': 3198, '石川東恩納': 4802}
print('人口合計:', sum(pop.values()))
```

- 市の統計を独自に合算した場合は、その旨と対象大字を明記する。
- 統計の基準日を必ず併記する。
- 異なる資料の数値が違う場合は、先に対象範囲と基準日を比較する。

### 5. 事実を照合する

- **2つ以上の情報源で一致**：通常の事実として記載できる。
- **公共機関1件だけ**：出典を明示するか、必要に応じて断定を弱める。
- **民間サイトだけ**：原則として記載せず、公共機関で裏を取る。
- 年号、数値、固有名詞は、原資料の表記と1件ずつ突き合わせる。
- 情報源間で矛盾する場合は統合せず、差異と考えられる理由を報告する。

### 6. 文章を作る

- 「位置・地形」「歴史」「人口」「文化・見どころ」など、地区間で比較しやすい見出しを使う。
- 各文について、根拠URLを答えられる状態にする。
- 公式資料の言い回しをコピーせず、平易な日本語に書き直す。
- 「絶景」「必見」などの過度な宣伝表現を避け、事実の記述に徹する。
- スマートフォンでスクロール2〜3回程度を分量の目安にする。ただし、重要な事実を分量調整だけで落とさない。

### 7. ページへ反映する

ユーザーが実装を依頼している場合だけ、次を行う。調査・比較だけの依頼ではファイルを変更しない。

1. `about-(地区名ローマ字).html`を作成または更新する（例：`about-ishikawa.html`）。
2. 本文先頭に`.area-disclaimer`を置き、自動収集を含む要約であること、誤りの可能性、情報源の掲載場所を明示する。
3. ページ末尾に「情報源」セクションを置き、採用したURLをすべてリンクで掲載する。
4. 最終更新日または調査日を表示する。
5. CSSやJavaScriptを変更した場合は、`AGENTS.md`に定められたキャッシュバスティング規則に従う。
6. 利用可能なブラウザでローカル表示を確認し、特にスマートフォン幅で本文、リンク、下部UIを検証する。
7. コミット、プッシュ、公開は、ユーザーが明示的に許可した場合だけ行う。

### 8. 定期更新する

本文を全自動で書き換えない。自動化する場合も「収集と差分検出」までに留め、HTMLの変更と公開には人の承認を挟む。

| 対象 | 更新頻度の目安 | 更新方法 |
|---|---|---|
| 人口・世帯数 | 3か月ごと | 数値と基準日だけを更新する |
| 施設・観光情報 | 6か月〜1年 | 閉鎖・新設を公式ページで確認する |
| 歴史・地理・文化 | 1年、または情報源更新時 | 原則維持し、変更時は差分を人が確認する |

定期更新時は次の承認方式を使う。

1. 現在のページと新しい調査結果との差分だけを報告する。
2. 運営者が差分を確認する。
3. 承認された内容だけを反映する。

### 9. 新しい地区の情報源を記録する

新しい地区を追加した場合は、下の「地区別の情報源」へ候補を追記する前にユーザーへ提示し、Skill自体の変更許可を確認する。

## 過去の教訓

- **教育委員会のPDFリーフレットを最初に探す。** 一般向けページだけでは、地域史の重要事実が大幅に欠落することがある。
- **資料館・図書館は情報源であり、見どころでもある。** 展示内容から、その地区で何が重要とされているか判断できる。
- **人口は定義によって変わる。** 字単位、地区、旧市域など、数値が示す範囲を必ず確認する。
- **要約前に事実を全件列挙する。** 最初から要約すると、地形、施設、年号、固有名詞を落としやすい。本文完成後、事実リストと1件ずつ照合する。
- 情報源ページの更新日を記録すると、次回確認の頻度を判断しやすい。
- 市公式の「地区ページ」がリンク集だけの場合もある。同一公式サイト内の観光、文化財、統計、資料館など別カテゴリも探す。
- PDFのテキスト抽出に失敗したら、取得を諦めず、PDF読取、ページ画像、表の目視確認など別の方法を使う。
- 大字が丁目単位で分かれる場合がある。一部だけ拾わず、統計表の全行を確認する。
- 検索結果の要約には別サイト由来の内容が混ざる場合がある。本文と原資料を根拠にする。

## 完了時の確認

- すべての重要な事実に一次情報または信頼できる公的根拠がある。
- 年号、数値、固有名詞を原資料と照合した。
- 人口の対象範囲と基準日を明記した。
- 原文の長いコピーや推測による補完がない。
- 使用したURLと調査日を記録した。
- 実装した場合は、意図したファイルだけが変更され、表示とリンクを確認した。
- 外部変更は、ユーザーから得た権限の範囲内に限定した。
