# 店舗主からのご連絡：段階移行

## 現在の範囲

- 管理者ページの「店舗主からのご連絡を管理」から専用画面を開く。
- 管理者認証後、受付一覧・店舗番号・店舗名・受付日時・連絡内容・メールアドレスを閲覧する。
- 対応状況（未確認・対応中・対応済み）と管理者用メモを保存する。
- 同じ連絡を別の画面で更新している場合は上書きを拒否する。
- 非公開の専用テーブルに保存し、公開お知らせAPIの対象に含めない。
- 受付API・新着通知・「その他」の条件付き送信を実装済み。ただし通知専用Apps Scriptの設置と実メール確認が未完了のため、本番切替は無効のままとする。店舗主側はGoogleフォームへの送信を継続する。公開用下書きの作成は未実装。
- Googleフォームの既存回答の取込は行っていないため、一覧は空の状態で始まる。

## 保持と見直し

連絡内容・メールアドレスは対応状況にかかわらず当面保持する。自動削除は設けない。
本番受付の開始日は未確定。切替時に記録し、その半年後に保存期間を見直す。
将来の削除方針では通知メール・フォーム・バックアップも併せて扱う。

## 次の段階

1. [通知設定と切替手順](owner-contact-mail-setup.md)に従い、通知専用Apps Scriptの設定・メール送信許可を行う。
2. `CONTACTS_LIVE=test` で店舗番号0だけを接続する。
3. 実送信・管理画面の受信・状態とメモ保存・メール受信を確認する。
4. `CONTACTS_LIVE=true` で本番の「その他」のみ切り替える。修正・削除依頼は現行のまま維持する。本番受付開始日と半年後の見直し日を記録する。

## 技術情報

- 管理画面：`admin/contacts.html`（既存の管理者Workerで配信）
- API：`GET /api/v1/admin/contacts`、`PUT /api/v1/admin/contacts/:id`
- DB：`owner_contacts`。状態・メモの更新日時、最終更新者、版番号を記録する。
- スキーマ：`admin-notice-api/migrations/0004_owner_contacts.sql`。既存テーブルは変更しない。
- 検証：`node scripts/test_owner_contacts.js`、`node scripts/test_owner_contacts_ui.js`
- UI検証はローカルの架空データだけを使用する。本番DBにテスト連絡を挿入しない。
- 新規受付：公開Workerの `POST /api/v1/contacts`。GETでの個別連絡取得は提供しない。
- 二重送信：受付IDと本文のフィンガープリントで再送を識別。同じIDの別内容は拒否する。ブラウザを再読み込みした場合はIDが変わるため、完全な重複排除ではない。
- 迷惑送信対策：サイズ上限、入力検証、ハニーポット、秘匿化したIP単位で15分10件の制限。店舗主本人の確認を行う仕組みではない。
- 通知：DBに送信待ち記録を保存し、即時送信後も未完了なら10分ごとの定期処理で再試行。メール側の失敗は連絡の受付成功を取り消さない。
- 通知の配送完了は送信サービスへの引き渡し確認を意味し、受信箱への到着保証ではない。応答喪失やGoogle側キャッシュ消失時には通知が重複する可能性がある。
- 新着メールに本文・連絡先は含めず、受付番号と管理画面へのリンクのみを載せる。
