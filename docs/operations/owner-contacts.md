# 店舗主からのご連絡：段階移行

## 現在の範囲

- 管理者ページの「店舗主からのご連絡を管理」から専用画面を開く。
- 管理者認証後、受付一覧・店舗番号・店舗名・受付日時・連絡内容・メールアドレスを閲覧する。
- 対応状況（未確認・対応中・対応済み）と管理者用メモを保存する。
- 同じ連絡を別の画面で更新している場合は上書きを拒否する。
- 非公開の専用テーブルに保存し、公開お知らせAPIの対象に含めない。
- 今回は管理機能のみ。店舗主側はGoogleフォームへの送信を継続し、新規受付API・新着通知の切替・公開用下書きの作成機能はまだ接続していない。
- Googleフォームの既存回答の取込は行っていないため、一覧は空の状態で始まる。

## 保持と見直し

連絡内容・メールアドレスは対応状況にかかわらず当面保持する。自動削除は設けない。
本番受付の開始日は未確定。切替時に記録し、その半年後に保存期間を見直す。
将来の削除方針では通知メール・フォーム・バックアップも併せて扱う。

## 次の段階

1. 「その他」の新規受付、重複防止、送信成功・失敗表示、迷惑送信対策を実装する。
2. 新着メール通知の送信手段と設定を整える。
3. 非公開閲覧・保存・通知・失敗時の動作をテスト用店舗で確認する。
4. 本番の「その他」のみ切り替える。修正・削除依頼は現行のまま維持する。

## 技術情報

- 管理画面：`admin/contacts.html`（既存の管理者Workerで配信）
- API：`GET /api/v1/admin/contacts`、`PUT /api/v1/admin/contacts/:id`
- DB：`owner_contacts`。状態・メモの更新日時、最終更新者、版番号を記録する。
- スキーマ：`admin-notice-api/migrations/0004_owner_contacts.sql`。既存テーブルは変更しない。
- 検証：`node scripts/test_owner_contacts.js`、`node scripts/test_owner_contacts_ui.js`
- UI検証はローカルの架空データだけを使用する。本番DBにテスト連絡を挿入しない。
