# 沖縄県全体を見据えたSkill体系（検討中）

石川マップで確立した調査・確認・公開手順を、具志川、勝連、与那城、将来は沖縄県内の他市町村・地区にも適用できる体系へ育てるための方針を記録する。

沖縄県全体への展開は長期目標であり、全地域の実装を約束するものではない。後から大きな修正が発生しにくい共通ルールを先に整え、実際に追加する地域から得た知見で段階的に改善する。

## 基本方針

- 全県対応を想定するが、実例のない機能を先回りして大量に実装しない。
- 調査方法、データの識別方法、根拠記録、確認・承認方法を優先して共通化する。
- 地域固有の資料、境界、店舗、歴史、ニュースは地域ごとに調査する。
- 石川マップの安定運用を守り、新地区の試作を既存本番から隔離する。
- 実例で通用しなかったルールだけを修正し、その理由と影響範囲を記録する。

## 地域階層

市町村と市町村内の地区を混同しない。少なくとも次の階層を区別できる状態を目指す。

```text
都道府県
└─ 市町村
   └─ 地区・旧市町村域
      └─ 大字・町丁目・自治会等
```

各階層の境界は一致するとは限らない。サイトで採用する範囲と、行政・統計上の範囲を別々に説明できるようにする。

## 先に共通化するもの

- 地域を一意に識別する地域コード
- 店舗・施設IDの地域横断通し番号
- 境界データの座標系、座標順、出典記録
- 資料名、URL、発行主体、資料年度、確認日、利用条件
- `確定候補`、`要確認`、`保留`などの確認状態
- 地域間で共有する境界線の管理方法
- 公開前の管理者確認
- パソコン、iPhone、Androidの実表示確認
- 調査結果と公開データを分ける承認手順

## 実例ができてから決めるもの

- 沖縄県全体の画面デザイン
- 地域選択画面と地域横断検索
- 一つのサイトへ統合するか、地区別構成を続けるか
- サイト全体の名称とURL構成
- 地域単位の読み込み・キャッシュ方法
- ニュースや店舗を横断表示する方法

## Skillの役割

| Skill | 担当 | 将来の課題 |
|---|---|---|
| `$area-boundary-survey` | 市町村・地区の定義、外周調査、境界データ、形状検査 | 沖縄県共通情報源、離島・飛び地、共有境界検査を実例で改善 |
| `$area-profile` | 地理、歴史、人口、文化、地区紹介 | 新しい自治体ごとの一次情報源を追加 |
| `$poi-survey` | 店舗・施設の実在、住所、座標、カテゴリ、状態 | 地域コードと境界内判定を将来強化 |
| `$ishikawa-local-news` | 石川地区のニュース | 実際の他地域展開時に、地域指定可能な別Skillまたは共通方式を検討 |
| `$responsive-device-qa` | 端末別の表示・動作確認 | 地域選択や大規模データ読み込みを追加した場合の検証項目を追加 |

すべてを一つのSkillに統合しない。それぞれの責任範囲を保ち、地域追加の流れは運営資料で接続する。

## 段階的な検証

1. 石川で既存手順とデータを確認する。
2. 具志川を最初の新地区候補として、境界調査から試す。
3. 具志川で生じた例外を、一般化できるものだけSkillへ反映する。
4. 勝連・与那城で同じ手順を再検証する。
5. うるま市外の1市町村で、情報源や行政区分の違いに対応できるか確認する。
6. 複数地域の実運用結果を基に、サイト構成と共通データ基盤を判断する。

## 見直しの原則

- 一地域だけの特殊事情を、理由なく全地域の必須ルールにしない。
- 共通ルールを変更する場合は、既存地域への影響を先に確認する。
- Skillの更新だけで公開データを自動変更しない。
- 自動収集・自動検査を追加しても、重要な差分の公開には人の承認を残す。
- 県全体へ到達しなくても、作成済み地域が単独で安定運用できる構成を維持する。
