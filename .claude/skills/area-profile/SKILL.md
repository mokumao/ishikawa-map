# 地区プロファイル調査スキル（「○○について」ページの作成・更新）

地図サイトで扱っている地区の紹介文を、**公共機関の一次情報を優先し、複数ソースで裏を取って**
作成・更新するための標準手順。2026-08-02の石川地区で確立した。

将来、石川以外の地区（うるま市具志川・勝連・与那城、沖縄本島の他市町村、県外）へ
展開したときも、この手順をそのまま使い回せるように設計している。

## 設計思想

`poi-survey` スキルと同じ思想を、地区の説明文に適用したもの。

1. **AIの記憶から書かない** — 必ずウェブ上の実在するページを読んでから書く
2. **公共機関を最優先** — 市町村公式 > 都道府県公式・公文書館 > 観光協会・公民館 > その他
3. **丸写しはしない** — 著作権に配慮し、事実を抽出して自分の言葉で再構成する
4. **出典と調査日を画面に出す** — 読者が自分で一次情報を確認できる状態にする
5. **数値と文章を分けて考える** — 人口などの数値は機械的に更新できる。歴史・文化の
   文章は滅多に変わらないので、変えるときは人が確認する（後述「Step 7」）

## 禁止事項（重要）

- **AIの知識だけで歴史や地名の由来を書かない。** もっともらしい誤りが混ざる
- **公式サイトの文章をそのままコピーしない。** 事実を抽出し、要約・再構成する
- **裏の取れない数値を書かない**（「人口約2万人」等の概数も、出典なしでは書かない）
- **推測を断定で書かない。** 情報源が1つしかない事実は、そう分かる書き方にするか落とす
- Googleマップ・NTTタウンページの自動収集は `poi-survey` と同様に禁止

## 手順

### Step 0: 準備

- `git pull origin main` を実行
- 対象地区と、それを所管する自治体を確定する
  （例：石川地区 → 沖縄県うるま市 / 旧石川市）
- 下の「地区別の情報源」表に既に行があればそれを使う。無ければ Step 1 から作る

### Step 1: 情報源リストを作る（公共機関から順に）

次の順で探し、見つかったURLを「地区別の情報源」表に記録する。

| 優先 | 種別 | 探し方の例 |
|---|---|---|
| 1 | 市町村公式サイトの地区紹介ページ | `(市町村名) (地区名) 紹介` `site:city.xxx.lg.jp` |
| 2 | 市町村公式の統計ページ（人口・世帯数） | `(市町村名) 大字別人口 統計` |
| 3 | 市町村公式の「市の紹介」「あゆみ」「歴史」 | `(市町村名) 市の紹介 合併 由来` |
| 4 | 都道府県公文書館・県公式 | `(都道府県) 公文書館 (地区名)` |
| 5 | 観光協会・物産協会（公的性格が強いもの） | `(市町村名) 観光協会 (地区名)` |
| 6 | 公民館・図書館・郷土資料館 | `(地区名) 公民館` `(市町村名) 市史` |

**注意点**
- 検索結果の要約だけで判断しない。**必ず WebFetch でページ本文を読む**
- 個人ブログ・まとめサイトは、事実の裏取りには使わない（存在のヒントまで）
- Wikipediaは「どんな事実があるか」を知る手がかりには使ってよいが、
  **記載の根拠にはしない**。同じ事実を公共機関のページで確認できたときだけ採用する

### Step 2: 本文の収集

各URLに対して WebFetch を実行し、次を指示して抽出する。

```
このページに書かれている(地区名)に関する事実を、漏れなく列挙してください。
地理・地形、歴史（年号と出来事）、文化・伝統、産業、観光・施設、
面積・人口などの数値を、記載されているとおりに抜き出してください。
ページに書かれていないことは推測せず「記載なし」としてください。
```

抽出した事実は、**どのURLから来たかを必ずセットで**メモしておく（後で出典表示に使う）。

### Step 3: 人口・世帯数の取得

市町村公式の統計ページには、たいてい「大字別人口及び世帯数」のPDFがある。

1. 統計ページを WebFetch し、**PDFの直リンクURLとファイル名の規則**を確認する
   （うるま市の例：`/documents/8736/ooaza2603.pdf` = 令和8年3月末。
   `ooaza` + 和暦2桁 + 月2桁 という規則）
2. 最新月のPDFのURLを WebFetch する。
   **PDFはWebFetchではテキスト化できないことが多いが、ローカルに保存される。**
   保存先パスが結果に出るので、それを **Read ツールで読む**（PDFを直接読める）
3. 対象地区に属する大字の行をすべて拾い、合計する
   （石川地区の例：大字名が「石川」で始まるもの19件）
4. **合計はBashで計算し、暗算しない。** 桁の読み違いを防ぐため

```bash
python3 -c "
pop = {'石川':3198, '石川東恩納':4802, ...}
print('人口合計:', sum(pop.values()))
"
```

**表示上の扱い**
- 市の統計をこちらで合算した数値は、その旨を明記する
  （例：「うるま市の大字別人口統計から、石川地区の大字を合算」）
- 統計の基準日（○年○月○日現在）を必ず併記する

### Step 4: 事実の照合

- **2つ以上の情報源で一致した事実** → そのまま書いてよい
- **公共機関1つのみ** → 書いてよいが、断定を弱めるか出典を明記する
- **民間サイトのみ** → 原則書かない。どうしても入れたい情報は公共機関で裏を取る
- 年号・数値・固有名詞は、書いたあとに元ページの表記と1件ずつ突き合わせる

### Step 5: 文章を作る

- **段落ごとに「位置・地形」「歴史」「人口」「文化・見どころ」**のような見出しを付ける
  （地区が変わっても同じ構成にすることで、他地区展開時に比較しやすくなる）
- 1文ずつ「これはどのURLから来た事実か」を答えられる状態にする
- 公式サイトの言い回しをそのまま使わず、平易な日本語に書き直す
- 過度な宣伝表現（「絶景」「必見」等）は使わない。事実の記述に徹する
- 分量の目安：スマホ1画面をスクロール2〜3回で読み切れる程度

### Step 6: ページへの反映

1. `about-(地区名ローマ字).html` を作成／更新する
   （石川の例：`about-ishikawa.html`）
2. **本文の先頭に注意書き（`.area-disclaimer`）を必ず置く。**
   AIが自動収集してまとめた文章であること・誤りがありうること・
   情報源を下に載せていることを明示する（読者が判断できるようにするため）
3. **ページ末尾に「情報源」セクションを必ず置く。** 使ったURLをすべてリンクで並べる
4. **「最終更新日（調査日）」をページに表示する**
5. CLAUDE.mdのルール通り、`style.css` を変更したら各HTMLの `?v=` を更新する
6. ローカルプレビューで表示を確認してからコミット・プッシュする

### Step 7: 定期更新の方針（重要）

**全自動で本文を書き換えることはしない。** 理由：

- 情報源のページ構造が変わると、誤った内容を拾っても気づけない
- 歴史・文化の記述は滅多に変わらないのに、AIが書き直すたびに表現が揺れる
- 誤りがそのまま公開サイトに出てしまう

そこで、**変わるものと変わらないものを分けて扱う**。

| 対象 | 更新頻度の目安 | 更新のしかた |
|---|---|---|
| 人口・世帯数 | 3か月ごと | 数値のみ差し替え。基準日も一緒に更新する |
| 施設・観光情報 | 6か月〜1年 | 閉鎖・新設がないか公式ページを確認 |
| 歴史・地理・文化 | 1年、または情報源の更新時 | 基本は変えない。変えるときは差分を人が確認 |

運用は `poi-survey` の読者投稿と同じ**承認方式**を推奨する：

1. 定期的にこのスキルを実行し、**現在のページと新しい調査結果の差分だけを報告**する
2. 差分を運営者が確認する
3. 承認されたものだけをページに反映してコミットする

将来GitHub Actionsで自動化する場合も、**自動化するのは「収集と差分検出」まで**とし、
HTMLの書き換えとプッシュは人の承認を挟む（Issueや差分ファイルを作るところまで）。

## 過去の教訓

- **要約すると事実を落とす。これが一番やりがちな失敗**
  （2026-08-02: 石川の初稿で「戦前は現在の沖縄市を中心とする行政区に含まれていた」
  「屋敷はフクギで囲まれた碁盤の目の集落だった」「伊波丘陵は標高87メートル」
  「東恩納博物館」「伊波集落は先史時代からの生活の場」を落としていた。
  ユーザーが元ページのスクリーンショットを見て気づいた）
  → **WebFetchで「1つ残らず箇条書きで列挙してください。推測は加えず、
  書かれていることだけを」と指示して事実リストを作り、書き終えたあとに
  そのリストと本文を1件ずつ突き合わせる**。ざっくり要約させると必ず抜ける
- WebFetchの抽出は指示の粒度で結果が変わる。「詳しく抜き出して」程度だと
  主要な段落しか返らないことがあるので、上記のように**網羅を明示的に要求する**
- 情報源ページの「更新日」を確認しておくと、次回の更新頻度を判断できる
  （2026-08-02: うるま市の石川エリアページは2023年12月8日更新のまま
  = 2年半以上変わっていない。歴史・文化の記述は年1回の確認で十分）
- 市公式の「地区ページ」が自治会リンク集だけのこともある
  （2026-08-02: うるま市の石川地区ページには歴史・人口の記述が無く、
  代わりに「うるま市の魅力」配下の石川エリアページに詳しい記述があった）
  → **1ページ見て情報が無くても諦めず、同じサイト内の別カテゴリを探す**
- 人口統計PDFは WebFetch ではテキスト抽出に失敗するが、
  **ローカル保存されたファイルを Read で読めば表を正しく読み取れる**
- 大字が丁目単位で細かく分かれていることがある（石川は19件に分かれていた）。
  一部だけ拾うと数千人単位で数字がずれるので、**必ず全件を数える**
- 検索エンジンの要約は、Wikipediaの記述を公式サイトの内容として混ぜて返すことがある。
  **要約を信じず、必ず本文を読む**
