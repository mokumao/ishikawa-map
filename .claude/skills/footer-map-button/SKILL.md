# 下部「地図」ボタン・バーのサイズ統一スキル

石川マップには画面左下に「地図」ボタン（＋隣接するもう1つのボタン）を置いた
白いバーが、複数のページに存在する。これらのサイズ（特に**縦の高さ**）が
ページごとに少しずつ異なっていることに2026-08-12、ユーザーが複数ページの
スクリーンショットを見比べて気づいた（詳細は「発見の経緯」参照）。

**このスキルの目的：新規ページ作成時・既存ページの見直し時に、必ず基準値と
実測値を一致させる。目分量や「だいたい同じ」で済ませない。**

## 基準（正）となる値

**基準ページ：`index.html` の画面下部タブバー（`#bottomTabs` / `.bottom-tabs`、
`.bottom-tab-btn`）。** 石川マップで最初に作られた・最も見られる画面なので、
他の全ページをこちらに合わせる（逆はしない）。

モバイル幅（375px相当）で実測した値（2026-08-12確認）：

| 要素 | 値 |
|---|---|
| バー（`.bottom-tabs`相当）の高さ | **51px** |
| バーのpadding | `8px 10px`（横幅はページのレイアウトに応じて調整してよい。**縦8px**が高さを決める） |
| バーの下の余白（margin-bottom） | **18px**（元は地図の著作権表示スペース用だが、他ページも下部の見た目の高さを揃えるため同じ値を入れる。2026-08-13追加） |
| 「地図」ボタンの高さ | **34px** |
| 「地図」ボタンの幅 | **`index.html`の地図画面は3ボタン均等**。その他のページは**113px固定** |
| ボタンのpadding | `2px 4px` |
| ボタンのfont-size | `1.15rem`（≒18.4px） |
| ボタンのfont-weight | `700` |
| ボタンのborder | `2px solid #e53935` |
| ボタンのborder-radius | `7px` |

**バーの高さ（51px）を決めているのは実質「バー縦padding8px×2」＋「ボタンの高さ34px」。
ボタンの高さは`min-height`ではなく`padding`（縦2px×2）が決めている点に注意
（`min-height:34px`だけ設定して`padding`を大きくすると、paddingが優先されて
高さがオーバーする＝2026-08-12に実際に起きた不具合）。**

**幅はページによって次の2ルールを使い分ける（2026-08-27最終決定）。**

- `index.html`の地図画面下部にある「地図・店名・一覧」は、3ボタンを均等幅にする。`.bottom-tab-btn { flex: 1; }`を基準とし、`#bottomTabMap`も`flex: 1 1 0`にする。
- 上記以外のページでは、左端の「地図」ボタンを113px固定にする。flexでは`flex: 0 0 113px`、gridでは地図ボタンの列を113px固定にする。
- 2026-08-13の「全ページ113px固定」は過去の方針。2026-08-27のユーザー確認により、メイン地図画面では3ボタンの均等さを優先する方針へ更新された。過去方針を再適用しない。

## 手順

### 既存ページのサイズがずれていないか確認するとき

1. ローカルプレビューを起動し、モバイル幅（375px目安）で対象ページを開く
2. ブラウザのJS実行で実測する（目視・目分量で済ませない）。**高さだけでなく幅も測る**。例：
   ```js
   var bar = document.querySelector('対象ページのバーのセレクタ');
   var btn = document.querySelector('対象ページの「地図」ボタンのセレクタ');
   JSON.stringify({
     barHeight: bar.getBoundingClientRect().height,
     btnHeight: btn.getBoundingClientRect().height,
     btnWidth:  btn.getBoundingClientRect().width,
     // バー要素自体の高さだけでなく、下の余白（margin-bottom）も含めた
     // 「視覚的な占有領域」を必ず比較する（2026-08-13の教訓）
     bottomGap: window.innerHeight - bar.getBoundingClientRect().bottom
   });
   ```
3. 上の基準値と比較する。幅は、`index.html`の地図画面なら3ボタンが同幅、その他のページなら地図ボタンが113pxかを確認する
4. ずれていたら、該当CSSを基準値に合わせて修正する
   - 高さのズレ → 多くの場合`padding`が原因
   - 幅のズレ → `index.html`の地図画面では3ボタンのflex値、その他のページでは`flex: 0 0 113px`またはgrid列113px固定を確認する
5. `news/index.html`が対象の場合は、**必ず`scripts/fetch_news.py`のテンプレートにも同じ修正を入れる**
6. 修正後、再度手順2の実測で基準値と一致したことを確認する。**別の画面幅（例：375pxと330pxの2パターン）でも実測し、メイン地図画面は3ボタンが均等、その他のページは地図ボタンが113px固定であることを確認してからコミットする**

### 新しいページを追加するとき（左下に「地図」ボタンを置く場合）

1. ゼロから作らず、既存の一致済みページ（`about-site.html`等）のCSS・HTML構造をコピーする
2. 独自の値を思いつきで書かない。上の「基準となる値」表の数値をそのまま使う
3. 実装後、必ず手順2の実測チェックを行い、51px／34pxと一致することを確認する
4. このSKILL.mdの「現在この見た目を使っている場所」表に新しいページを追記する

## 発見の経緯（2026-08-12〜13）

- ユーザーが複数ページのスクリーンショットを見比べ、「地図」ボタンとバーの
  縦の大きさがページごとに違うことを指摘
- 実測したところ、原因は**ボタンのpadding（縦方向）の値がページごとに異なっていた**こと
  （基準:`2px 4px`に対し、`about-site-footer`系は`6px 4px`、newsページは`9px 4px`
  になっており、`min-height:34px`を指定していても実際の高さはpaddingに押し上げられていた）
- `.info-panel-footer`/`.info-map-btn`（情報パネル）は既にCodexが基準と完全一致する
  値で実装済みだったため、修正不要だった
- 全て`padding: 2px 4px`に統一することで解消。あわせて本SKILL.mdを新設した

**2026-08-13追記：幅の固定ルールを追加**
- 高さは統一できたが、幅は各バーの列数（グリッド3等分・`width:32%`等）に
  依存する可変値のままだった（実測では111〜113pxとほぼ近い値だったため
  当初は許容していた）
- ユーザーから「隣のボタンの有無・数に関わらず、地図ボタンは常に左下・
  常に同じ縦横サイズにしたい」という明確な要望があり、幅も113px固定に変更
- 実装は`flex: 0 0 113px`（or grid列を`113px`固定）とし、隣接ボタンは
  `flex:1`のまま可変幅で残り空間を埋める方式に統一した

**2026-08-13同日追記：index.html本体の3ボタンは幅固定の対象外に訂正**
- 上記の対応を`index.html`の「地図・店名・一覧」3ボタンにも適用した結果、
  画面幅が狭い端末（320px）で「地図」だけ113px固定のまま残り、店名・一覧が
  85.5pxまで縮んで不揃いに見える不具合をユーザーが発見（実機スクリーンショットで指摘）
- 原因：「地図」ボタンの幅を独立した固定値にすると、共有される残り幅が
  少ない狭い画面では他のボタンとの差が目立ってしまう
- 対応：`index.html`本体のこの3ボタンに限り、`#bottomTabMap`の固定幅指定を
  撤回し、3ボタンとも`.bottom-tab-btn`の`flex:1`による均等割りに戻した
  （＝2026-08-12以前の挙動と同じ）。他ページ（1〜2ボタンの構成）は
  引き続き「地図」ボタン113px固定のままとする

**2026-08-13さらに追記：上記の訂正を再度取り消し、113px固定に統一（当時の決定）**
- 上記の「均等割りに戻す」対応により、今度は**メイン画面の「地図」ボタン自体の
  幅が画面幅で変動する**副作用が発覚（375px幅で113px、390px幅で118px）。
  ユーザーが実機（about-ishikawa/about-site/newsページ）のスクリーンショットを
  複数枚見比べ、「メイン画面の地図ボタンと他ページの地図ボタンの大きさが違う」
  と再度指摘
- 実測して確認したところ、他ページは常に113px固定である一方、メイン画面は
  画面幅に応じて113〜118px超で変動しており、両者は原理的に完全一致しない
  （3ボタンの均等割り幅が偶然113pxになるのは画面幅がちょうど375pxのときだけ）
- 「メイン3ボタンの均等さ」と「地図ボタンの全ページ統一」はトレードオフの関係にあり、
  両立させるには320px程度の狭い端末で店名・一覧が地図より小さくなることを
  受け入れる必要があると判断。ユーザーに二択で確認し、**「全ページで地図ボタン
  113px固定」を明確に選んでもらった**ため、`index.html`本体にも
  `#bottomTabMap { flex: 0 0 113px; }` を再度適用し、当時の仕様とした
- 教訓：見た目の統一ルールを一部のページ・条件だけ例外にすると、その例外自体が
  新たな不一致を生むことがある。例外を作る場合は、それによって発生しうる
  「別の観点からの不一致」まで検討してから適用すること

**2026-08-27追記：メイン地図画面の3ボタン均等を最新仕様として再採用**
- ユーザーが実機で「地図」だけ大きく「店名・一覧」が小さい状態を再確認し、メイン地図画面の3ボタンを均等幅にするよう明示的に変更した。
- `index.html`の地図画面だけ`#bottomTabMap { flex: 1 1 0; }`とし、3ボタンを均等にする。
- 情報パネル、紹介ページ、ニュース、店舗詳細など、その他のページは従来どおり地図ボタン113px固定を維持する。
- この2026-08-27の決定が最新であり、2026-08-13の「全ページ113px固定」より優先する。

**2026-08-13さらに追記：バー下のmargin-bottom（18px）も統一対象に追加**
- 「地図」ボタンの大きさが全ページで揃った後、ユーザーから改めて
  「各ページ下の白いバーの高さがメイン画面より短い」との指摘
- 実測するとバー自体の高さ（51px）は既に一致していたが、メイン画面の
  `.bottom-tabs`だけが地図の著作権表示（Leaflet attribution）用に
  `margin-bottom: 18px`を持っており、バーの下に追加の余白があった。
  他ページにはこの余白が無かったため、下部全体の見た目の高さがメイン画面
  より短く見えていた
- 対応：`.about-site-footer`と`news/index.html`の`.bottom-bar`にも同じ
  `margin-bottom: 18px`を追加。`.info-panel-footer`は元々この値を
  持っていたため変更不要だった
- 教訓：「バーの高さ」を実測するときは、バー要素自体の`height`だけでなく、
  `margin`等の周辺の余白も含めた「視覚的な占有領域」で比較すること。
  要素単体のCSSプロパティが一致していても、周辺の余白が違えば
  見た目の印象は変わる
